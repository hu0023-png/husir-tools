🧹 SVG Optimizer & Minifier

Strip the cruft · shrink icon files · 100% in your browser

📘 About this tool

SVG icons exported from design tools carry a lot of invisible baggage: editor metadata, XML declarations, comments, empty group layers, and coordinates with a dozen decimal places. None of that helps the icon render — it only makes the file bigger and the code harder to read. This optimizer parses your SVG, removes that cruft, optionally rounds long decimals, and rewrites the file as compact, production-ready markup.

Use it before you ship an icon set to a website, an app, or a design system — smaller SVGs load faster and keep HTML cleaner. Paste code from your design tool, or upload a .svg file directly. You control every cleanup with the checkboxes: strip comments, remove metadata and empty groups, round decimals to two places, and minify or pretty-print the final output. A live preview and byte-count comparison let you verify the result before you download it.

Because everything runs locally in your browser with no upload, the tool is safe for private or client files. For extra safety it also strips <script> elements, foreignObject, and event-handler attributes from any SVG you process, so a downloaded icon can never carry executable content. The parser is strict: if your file is not well-formed XML, it will tell you instead of guessing. Note this is a conservative cleaner, not a full vector re-drawer — it never merges paths or removes shapes, so the visual result stays identical.

🧽 What exactly gets removed?
Comments, the <?xml?> declaration and doctype, <metadata>, empty <g> layers, <script> and foreignObject, and on* event attributes. Optional: extra decimal places and all line breaks.

📉 How much smaller will my file be?
Icons exported from tools like Illustrator, Figma, or Inkscape often shrink 20–50% just from removing metadata, comments, and whitespace — sometimes more. A hand-written icon may only drop a few percent; that is normal.

🎨 Will the icon still look identical?
Yes. This tool only removes information the renderer ignores or recreates (whitespace, comments, empty layers). It never alters paths, colors, gradients, or dimensions, so the pixels should not change.

🖼️ Is it safe to run on files I cannot share?
Yes — nothing is uploaded anywhere. The file is parsed and rewritten entirely inside your browser, which makes this a good fit for client work or proprietary icon sets.

⚠️ Why did I get a “not well-formed XML” message?
SVG is XML, so it must follow XML rules: every tag closed, attributes quoted. Many web pages contain inline SVG with HTML-style looseness — copy just the <svg>…</svg> block, or save the icon as a real .svg file first.

🧩 Does it work for animated or complex SVGs?
Simple animations inside <animate> survive fine. Scripted or HTML-embedded SVGs are deliberately sanitized, so interactive widgets should not rely on this output.

📦 What the cleaner does
1. Parse SVG as strict XML
2. Drop comments, XML declaration, doctype, <metadata>, empty <g> layers
3. Strip <script>, foreignObject, and on* event attributes (sanitize)
4. Optional: round decimals to 2 places & remove whitespace between tags
5. Re-serialize to clean SVG markup
