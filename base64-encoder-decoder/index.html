🔡 Base64 Encoder & Decoder

Text ⇄ Base64 · UTF-8 safe · runs 100% in your browser

📘 About this tool

Base64 converts any text into a safe 64-character alphabet (A–Z, a–z, 0–9, +, /) so data can travel through systems that only handle plain ASCII — email, JSON, URLs, and config files. This tool encodes and decodes entirely in your browser: type or paste plain text to get its Base64 form, or paste Base64 to read the original text back.

Full Unicode is supported (emoji, Chinese, accented letters) because the page converts text to UTF-8 bytes before encoding. Developers reach for Base64 when embedding small images in HTML or CSS as data: URIs, pasting tokens into configs, decoding the payload of a JWT, or inspecting email attachments. Nothing is uploaded — the page works offline with zero network calls.

💬 Is Base64 encryption?
No. It is reversible encoding, not security. Anyone can decode Base64, so never use it to protect passwords or secrets — it only makes data safe to transport, not private.

💰 Why do strings end with = ?
Base64 encodes 3 input bytes as 4 characters. When the last group is short, it pads the output with = so the length is always a multiple of 4. “Hi” (2 bytes) becomes SGk=.

🌍 Does it work with Chinese, emoji, or accents?
Yes. Text is first encoded as UTF-8 bytes, so “你好，世界🌍” round-trips perfectly instead of turning into “?” marks.

🔗 What is URL-safe Base64?
Regular Base64 uses + and /, which have special meaning in URLs. URL-safe mode swaps them for - and _ and trims the padding, matching JWT and many API specs.

⚠️ Why did decoding fail?
Remove line breaks, check that you are using the matching alphabet (standard vs. URL-safe), and make sure padding is correct. If the decoded bytes are not valid UTF-8 text, this page shows “not valid text” instead of gibberish.

📐 Quick reference
3 bytes → 4 Base64 characters  ·  Output length = ceil(n / 3) × 4
Alphabet: A–Z a–z 0–9 + /   ·   Example: “Hi” → SGk=   “Hello” → SGVsbG8=
URL-safe: + → -, / → _, padding removed
